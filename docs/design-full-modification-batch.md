## §2 批次 0：共享地基

### T-01 「同层合并」机制
- **依据**：J3（已量到三次；最贵的一次是 h4 那 **31,397 字符**的手工合并）。
- **改动**：在一个答案里，允许同一层的多类事实同处——源码 ＋ 符号（名/行区间/契约首行）；死臂 ＋ 契约行（已在 `e52b3c2` 做出**参照实现**）；台账条目 ＋ `recorded/current` 指纹。实现上给这三类各一条**渲染函数**，共用一个"层内附加"的出口，而不是三处各拼字符串。
- **验收**：三个消费者各自的钉子（T-04/T-05/T-13）断言"并集 ⊆ 一次答案"；且**耦合钉子**：改坏该出口 ⇒ 三个消费者同时红。
- **规模**：中（1 个新模块 + 3 个调用点）。

## §10 下一批（维护者 2026-10-02 拍板：**排在第八轮之后**）

### T-26 截断要点名被扣掉的项（不只给个数）· 并给"路径归属"一条硬指路

- **来源（第八轮）**：`g4` 漏列一条按构造不可达的分支（`bands.rs:91 State::Closed`），而**分支栏的默认上限是 5 行**，
  截断行只写 `… truncated: 12 of 18 census lines withheld at the limit of 5; pass census: true …` ✗
  ⇒ **一个只报数量、不报名单的截断，读者无法判断被扣掉的是不是他要的那一条**。
- **判据**：① 截断行带上被扣行的**首标识**（有界，例如最多 5 个）；或按栏分别报数；② 反证：把上限调够时
  不许再出现这条截断行；③ 同批加一条"**路径归属**"的硬指路（"每一跳都要回源码定义处核，不许由命名推断"）——
  它对应第八轮 `s4`/`s6` 两处"把调用路径说错"的答案退化（同一批 54 次调用 exit 全 0 ⇒ 不是桥坏，是答案错）。

### T-25 修 A5：把"读不了"与"没有"分开

- **现象**（第八轮暴露，复核者用第七轮快照二进制确认是**继承缺陷**、不是本轮引入）：在一棵**读不了源码**的树上，
  `search --literal` 输出 `tree unavailable (…)` + `no matches`，而**退出码仍是 0**；同一棵树里 `grep` 有 3 条命中
  ⇒ **假阴性被报成了结论** ✗。
- **判据**：① 这种情况下**不许**报 `no matches`；② 第一行说清是"根读不了/源扫不到"还是"确实没有匹配"；
  ③ 退出码按协议定（0 = 作答；那么"读不了"要么非零、要么在首行明确声明不完整）；④ 反证：在一棵**读得了**的树上
  同一条命令仍必须报 `no matches`（不许把正常空结果也升级成错误）。


### T-24 给切口一个写通道（`apply {action: "cut"|"graft"}`）

- **来的地方**：维护者问「当前的工具调用，比如 graft、add、new 等是让 ai 手动生成的，还是调用了 cli 工具的」——
  查证结果是**混合的**：`new_project` 调 `build_time::scaffold::create_project`（桥 / CLI `new` / Studio 同一份）✓；
  `apply {add,edit,rename,delete,deepen}` 走 `runtime::AuthoringContext`（与 Studio 同一个执行器、默认只预览）✓；
  **而 graft 切口（`cut(…)`/`graft(…)`）只能手写在宿主源码里** ✗ —— 桥对它们只**数、报**
  （`toolchain/src/mcp/src/apply.rs:849/856/860/883`），`scaffold` 不写切口，CLI 也没有 `apply` 命令
  ⇒ **场景 S7（移动/重构）里涉及切口的部分没有写通道**：调用方得自己写出 `static_graft_plan!` 的语法，
  桥既不校验也不代写。
- **要与 T-15 一起想**：T-15 挂起的原因是"零件层没有可寻址身份"；切口这一条是它的邻居——两条合起来才是
  "深度方向上的可改点"完整的一块。
- **判据（2026-10-02 读现状后改写第一步）**：① ~~走内核既有的语法渲染~~ ✗ —— **内核没有渲染那一半**：
  `kernel/src/registry_core/syntax/entries/graft.rs` 只有 `graft_entries(source) -> Vec<GraftSyntax>`（**解析** ✓），
  而 Studio 的 `describe_graft`（`studio/app/graft.rs:341`）是**给读者看的描述**、不是写回源码的拼写 ✗
  ⇒ **第一步必须先在内核里造出"写出这条声明"的那一份实现**（与解析器并排，配**回环钉子**：渲染 ⇒ 用
  `graft_entries` 解析回来 ⇒ 结构相同 ✓，与采信台账那条同法），然后桥才可能"不手拼字符串" ✓。
  题面里也早写着"**渲染器**会原样发射这些表达式"（`graft.rs:66` 的字段文档）——那一半今天不存在 ✗。
  ② 预览必须给出**影响面**（哪些面被剪掉/绕过、哪些钉子会动）；③ **反证**：撤销声明 ⇒ 影响面回到原样；
  ④ 不许绕过父面规则与拓扑检查（与 `add`/`deepen` 同一条准入）。
