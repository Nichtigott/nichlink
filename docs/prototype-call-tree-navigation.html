调用树导航:树状显示版 结构画成树;调用方向就是横轴;解析维画在边上

这一版要回答的问题:把导航目标从"三列清单"换成树之后—— (a) 方向键能不能只用一条规则说清(← 上游 / → 下游,也就是调用方向本身)、 (b) 三种居中语义在树上还剩几种有意义的差别、 (c) "解析到哪个实现"能不能直接画在边上,让逃逸在图上就现形、 (d) "显示全树"要付什么代价——以入口为根的全树丢掉的到底是什么。

树的两侧不是"左/右"而是上游与下游:中心左边是调用它的节点,右边是它调用的节点, 每条边都由调用者指向被调用者——所以屏幕从左到右永远是调用方向,箭头永远朝右, 解析标签永远属于边的起点(调用方,它才有"解析到谁"这件事)。

两个视图同一条横轴:以中心为根画某个节点的邻域(上游在左、下游在右,按层截断), 以入口为根画入口以下的整棵调用树(不截断)。后者看着更「全」,实际上会丢东西—— 入口到不了的函数它一个都不画,所以它必须把丢掉的那些单列出来,并在留下的节点上标"＋N 上游未画"。 这一版把这件事画出来而不是藏起来。

驱动方式:点一下树或按任意方向键。← 上游、→ 下游、 ↑↓ 同层循环、Enter 以光标生根、Esc 光标回中心、 123 层数、Tab 搜索。 鼠标点节点 = 移动光标("光标即中心"下同时生根)。每次动作后状态面板与日志都写清发生了什么。
