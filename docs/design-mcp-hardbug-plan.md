# 明确计划：先把"当前设计的最好"做出来，再一次性测试

维护者的两点要求（本文的全部依据）：① **潜力是解决传统 AI 编程难题，但一直没实现** ⇒ 先把能力做到位；
② **一轮轮测试极耗 token** ⇒ **不要再"小改一测"**，把能力**分批做完、自证到位**，最后**只跑一次**大测试。

## 0. 判据与纪律（先说钱）

- **主 KPI**：每题**仪器调用数 / 步数**（白跑单列）；token（原始 / carried / 真实 with-cache）为次；
  质量红线不变：**根因命中、构造反证、修复最小性、附带损伤、判据信息一条不丢**。
- **每一相"做完"＝自证**：新能力必须有（a）机械钉子、（b）答案键文件（构造出的真值）、（c）自报边界。
  **不靠外部测试**就知道它成立 ⇒ 这就是省 token 的关键。
- **不跑对照臂**：P1–P5 的验证一律用**我们自己的改前/改后两个二进制**在同一批树上跑（对照刚升 1.6.1，
  只在 P6 跑一次、且只跑新题；旧 21 题用 `CONTROL-FREEZE.md` 的冻结集）。
- **团队只在两处用**：⑴ P1–P5 做完后**一次性独立复核**（自建两个二进制 + 反证）；⑵ **P6 一次大测试**
  （两臂 + 审计）。不再一相一测。
- **不许过拟合三守**（沿用既有准则）：规则可判定且与用例无关（不写死文件名/数值）；能力用**新关卡**
  机械自证泛化；答案**永不点名具体缺陷**并自报边界。

## 1. 目标状态：桥应当能"一到两次调用"回答的四类难题

四类都**只需要现有事实的推导与打包**（树、声明、`direct_calls`、源码索引、计划/作用域产物、采信台账、
分支事实、覆盖映射）——**不需要新的解析范式、不需要运行期插桩**。这就是"当前设计的最好"。

### 能力 ① `consistency` —— 供应链驳杂（同族约定不一致）
- **输入**：`--parent <node>`（同族集合的来源）＋ `--by <signal>`（`api` | `field` | `export` | `slot` | `parts`；
  缺省＝所有已声明属性各给一行计数）。
- **输出（默认短档）**：`family root/control · 3 members` ＋ 每个成员一行（属性值）＋
  **`outliers: 1 of 3 (slider)`** ＋ 边界句。
- **信号必须可判定**：`api` = 该对象函数体内调用的 API 族前缀（由 `direct_calls` 归纳，写在答案里）；
  `field/export/slot/parts` = 声明字段（树里已有）。
- **边界自报**：只判"同族之间是否一致"，**不判**哪一边才是对的（那要契约/需求）；不覆盖运行期行为。
- **自证**：钉子（同族 8–30 个对象，注入一处漂移 ⇒ 恰好点名那一个）；答案键文件；反证（把漂移改回去 ⇒
  `outliers: 0`）。

### 能力 ② `conformance` —— 采信未落实（设计过、没继续执行；容忍演化）
- **输入**：`--anchor <anchor>`（标本）或 `--all`；`--baseline <current|entry:<n>>`（缺省＝台账**当前生效条目**）。
- **输出**：标本的**可推导形状指纹**（声明字段/零件/句柄/导出/调用族）＋ 同族逐个比对
  （`3 of 4 exhibit; slider lacks parts`）＋ **"声明了但没落实"栏**（文档或台账声明 但无实现/无门禁/无覆盖）
  ＋ 边界句（只判"有没有"，不判语义正确）。
- **演化容忍**：基准取**当前生效条目**；约定本身变了 ⇒ **续期那一次就是变更事件**（租约语义）。
- **自证**：真台账（`provisional`）＋ 两个同族（一个照做、一个只缺一条声明）⇒ 恰好点名；反证（补齐 ⇒ 0）。

### 能力 ③ `why` —— 跨文件因果链（一次给上游决定性事实）
- **输入**：`--at <file:line|node>`；`--depth`（默认 2）。
- **输出（一次）**：① 调用者（含**跨成员**与**是否测试**，带 file:line）；② 是否进**发布树**（计划/作用域）；
  ③ 接线（切口 / `full`）；④ 是否被**特性门控**；⑤ 契约来源行；⑥ 与该点相关的采信条目。
  每条后面跟"这一条不覆盖什么"。
- **自证**：注入"入口没声明切口"这类因（症状＝运行期面不见了）⇒ 一次调用点名计划层事实；
  答案键 + 钉子；反证（补上声明 ⇒ 该行消失）。

### 能力 ④ `digest` —— 文件级摘要（单文件多算法）
- **输入**：`--node|--file`；默认 **≤20 行**，整表走显式开关。
- **输出**：算法/分支清单（按 doc 首行分组）＋ 每支覆盖情况 ＋ **构造上不可达的臂** ＋ 契约行
  ＋ 关键调用者（含成员）。
- **自证**：一个文件三套算法、其中一支写反（默认面绿、恰好一支没测到）⇒ 摘要点名那一支。

### 横切（不改判据、只减往返）
- **E1 答案预支下一跳**：每个答案尾注 `next <tool> {keys}`（`--list` 两轮 0 次调用 ⇒ 必须进答案）。
- **E2 形状进必经路径**：`apply` 拒绝**印完整可接受形状**；客户端 `--json` 任意位置；
  `callgraph`/`why` 无参时印 keys。
- **E3 默认短档扩到家族/范围题**：计数 + 边界两行**永不抽掉**，明细按默认条数抽样、整表走显式开关。

## 3. 每相的"自证"清单（模板，避免返工）

1. **钉子**：新能力 ≥2 条（一条正例、一条边界/反例），并**反证**能变红；
2. **答案键文件**：真值由**构造**给出（注入脚本 + 期望文件 + 判定脚本），不用题库；
3. **边界句**：写进工具描述与 `--list`（自我描述与行为一致）；
4. **前后对照**：同一批树上跑改前/改后二进制，给**调用数 / 步数 / 字符**三列（不跑对照臂）；
5. **判据信息一条不丢**：跑既有的答案键（根/边界/`withheld`/形状/台账 `next`）必须仍 PASS。

## 4. P6 唯一一次大测试（预先登记，避免临场改口）

- **题**：四类复杂 bug 注入（H1 供应链驳杂 → 能力①；H2 采信未落实 → 能力②；H3 跨文件因果链 → 能力③；
  H4 单文件多算法 → 能力④），每题带**构造真值 + 理想路径 + 必须拒绝的捷径**；参照与答案键放 `.audit/`。
- **两臂**：我们（P1–P5 后的桥） vs **codegraph 1.6.1**（只跑新题；1.5.0 冻结集作历史基线）。
- **判分（机械）**：根因命中（file:line + 机制）· **仪器调用数/步数** · token（原始/carried/真实）·
  是否**构造了反证** · 修复最小性 · 附带损伤。
- **证伪条件（先写死）**：若配 codegraph 的称职 agent 靠 `cat target/nichlink/out/*.tsv` + 手工推导也能
  拿下同类题，则判**我们无绝对优势**，只报"少调用/少往返"；**不许事后放宽**。
- **独立复核**：member 自建两个二进制、不引实现者报告、含反证。

## 6. 主战场是**调用数**，不是字节（第七轮逐次调用数据的结论）

按调用数归一后，三条轴的真实形态（第七轮）：

| 量 | mcp | cg | 含义 |
| --- | --- | --- | --- |
| 仪器调用 | 113 | 84（其中 `init` 23 次＝每棵树一次） | **答题调用 113 : 61 ⇒ 1.85×**（我们**零**索引成本，它每题树 1 次） |
| **每次调用回复字符** | **1,475** | 1,782（审计口径） | 我们**每次更便宜** ✓ |
| **每次调用推理字符** | **2,046** | 4,810 | 我们**每次想得更少** ✓（2.35×） |
| 推演：调用降到 84 | token ≈0.83× · 推理 ≈**0.43×** | — | ⇒ **同调用数下三条轴全面优于它** |

⇒ 结论：我们的**全部劣势只在"每题要问几次"**（5.1 次/题 vs 它 2.8 次/题）。它便宜是因为**动词少而粗**
（`init` 23 / `callers` 23 / `explore` 20 / `affected` 8 / `node` 3 / `impact` 3 / `query` 3），
一个 `explore "自然语言"` 或 `callers X` 就把一片信息给全；而我们是**按facet拆开**（`search`/`callgraph`/
`read`/`affected`/`check`/`census`），而且**必须先说出确切名字**才能问 ⇒ 猜名字 + 验证 = 多跳。

**每题调用差最大的题**：`r4` 8:2（Δ+6）、`s5` 7:3、`r2` 6:2、`fa` 7:3、`s7` 5:2、`r3` 5:2、`r1` 8:5、`fb` 6:3。

**新增两条杠杆（本文档 §1 之上的补充）**：

- **L1 `locate <symptom>`**（最高优先）：给定**症状串**（断言消息/报错/一句描述），**一次**返回排名候选
  （file:line + 符号 + 排名理由）：literal 命中 + doc 词重叠 + 调用图中心度 + 是否测试文件 + 所属成员；
  自报边界（排序不是判定）。**替代"猜名字"的 2–3 跳**。目标：`r4` 8→3、`r2`/`r3`/`s7`/`s8` →2、`r1` 8→5。
- **L4 流程表改写**：教"**一次问一件事、优先用 bundle（`why`/`locate`/`consistency`）**"，
  把"名字未知就逐跳"降级为最后手段（第七轮 `r1` 的 8 次调用**正好是流程表教的路径**）。

**"全面超越"的判定口径（P6 用，不许事后放宽）**：在**同一批新题**上，同时满足
① 根因命中率 ≥ 它；② **每题调用数 ≤ 它**；③ token（原始/真实）≤ 它；④ 推理字符 ≤ 它；
⑤ 构造反证/最小性不劣。**四条同时成立才写"全面超越"**，否则只报"代价轴占优"。

### W1.4 的落点侦察（2026-10-01，先量后做——**结论改变了它的优先级**）

第七轮"家族/范围题回复 13k"的构成被量开了：那不是一次大回复，而是**三次 `check`**（每题一个面一次）：

| 题 | 各次调用的回复字符 |
| --- | --- |
| `fd` | `status` 382 · **`check` 4649 / 4180 / 4173** |
| `fe` | `status` 383 · **`check` 4482 / 4165 / 4182** |
| `h1` | `status` 372 · **`check` 4629 / 3928 / 3935** |

再拆一次 `check`（当前二进制、`d-one-broken-mcp`，总计 3,532 字符）：

| 段 | 字符 / 行 |
| --- | --- |
| `not covered by …`（**各栏边界散文**） | **1,662 / 2** ← 最大一块，约 47% |
| `result …`（测试目标逐条） | 707 / 7 |
| `not covered:`（总账尾句） | 258 / 1 |
| 计数行（`unreferenced`/`respelled`/`census:`/`entry`…） | 约 470 |

⇒ **W1.4 的正确切法**：把**各栏边界散文**在默认档压成"一句必需短语 + `--list check` 全文"，
`census: true` 时仍给全文（并保留答案键依赖的 `not a coverage measurement`、`not covered:` 等必需子串）。
**预期**：每次 `check` −25%~30%（≈ −1.1k），三面题省 ≈3.3k；**风险**：边界散文是判据的一部分，
压缩必须逐子串核对答案键，且既有钉子多有断言 ⇒ 要一次改到位、逐条跑钉子。
**优先级结论**：收益中等、风险中等 ⇒ **排在结构面清单接线之后**（那件是 W4/W5 的前置，且是"别人做不到"的
那一类），不要先动它。

### W4/W5 的落点侦察（2026-10-01，先量后做）

- `toolchain/src/mcp/src/registry.rs` 的入口**都返回渲染好的字符串**（`registry` / `registry_brief` /
  `registry_with` / `registry_body` / `namespace`），**没有**"结构化面清单"可用；
- 带 `parts` / `exports` / `handle_traits` / `part_traits` 这些字段的**结构化发现**在
  `toolchain/src/build_time/src/discovery_cache.rs`（那里逐个字段名遍历）；
- ⇒ **W4 `consistency` 与 W5 `conformance` 都需要先把"结构化面清单（parent + 声明字段 + 成员归属）"
  接到 mcp 面**（一条只读的、与 `registry` 同源的分支），再谈"同族 × 属性"与"标本形状指纹"。
  这也是唯一一处**必须新增解析管线**的地方（W1–W3/W6 都只用现有事实）。**先做这件事，再做 W4/W5**；
  接线时守住"一条规则一份实现"：成员与字段都取自既有的发现/索引，不另写一套推导。

**第三轮回读（同日，把 W4 v1 的范围钉死）**：`FaceView`（`render_registry` 迭代的那个类型）只带
`path` / `kind` / `source` / `id` / `parent_resolved` —— **没有** `exports`/`handle_traits`/`parts` 这些
声明字段（它们在**构建期**的 `FaceSyntax::field` 上，`discovery_cache` 里的 `contract\t<name>\t<value>`
就是它们的缓存）。⇒ **W4 v1 不要卡在声明字段上**：
- 信号默认取 **`api`**：同族每个面**它自己文件里调用的名字族**（由既有 `direct_calls` 归纳，例如
  `*_world` 与 `*_local` 两族）——这正是维护者说的"供应链驳杂"（button 用相对坐标、slider/timeline 用
  世界坐标）那条；`--by kind|path|source` 三个便宜信号直接来自 `FaceView`；
- 面的来源只覆盖 **`Tree::Derived { faces, .. }`**（开发树的正路）；`Tree::Published` 那一支
  **明说"这一支的字段要另读记录/缓存"** 并指向 `registry`/`adopted`，不填默认值；
- 声明字段（`parts`/`exports`/`handle_traits`）留给 **W5 `conformance`** 从台账标本那一侧推导
  （标本的字段在**它的源文件**里，可以用同一条内核语法/文本路径读），不要为此先造第二套解析。
  ⇒ 这样 W4 **不需要**先重构 `registry_body`；第二轮回读里那条"拆 `face_rows`"仍是 W5 的前置。**第二轮回读（同日晚些，把落点收窄到函数级）**：结构化数据就在 `registry_body(&member, &arguments)`
（`toolchain/src/mcp/src/registry.rs:141`）**内部推导出来的那批面**身上——`build_time` 的
`discovery_cache.rs` 只是**缓存**（`FaceSyntax` 的字段读法见它第 157 行：对
`["parts","exports","handle_traits","part_traits"]` 逐个 `face.field(name)`），入口是
`update_discovery_cache` / `cached_parent_id`，**不适合**当只读查询面。⇒ 正确的接法：**在
`registry.rs` 里把 `registry_body` 现在"推导面再渲染"的那一步拆出一个只读的中间层**
（`fn faces_of(member) -> Result<Vec<FaceRow>, String>`，`FaceRow { parent, node, module, kind,
exports, handle_traits, parts, part_traits }`），让 `registry_body` 与未来的 `consistency`/`conformance`
**共用同一份推导**；`--parent` 的同族集合就是这张表按 `parent` 分组（同族 = 同一 parent 下的面）。
**这一步只重构、不改答案**：先钉住"`registry` 的输出逐字节不变"，再加 `consistency`（钉子+答案键按 §7）。

**每项的验证列（统一模板）**：改前/改后两个二进制在同一批树上跑 ⇒ 给**仪器调用数 / 步数 / 回复字符**
三列 + 既有答案键仍 PASS（判据信息一条不丢）。**不跑对照臂。**

## 5. 明确的"不做"

通用压缩（收益递减）· 为省 token 删判据信息 · 为对齐 codegraph 改我们的路径 · 新增第二份实现/第二套词法 ·
在 P1–P5 期间跑对照臂 · 一相一测。
