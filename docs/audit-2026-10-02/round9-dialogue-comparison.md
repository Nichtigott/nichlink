**我们递出去的是"数据 + 它意味着什么"（边界、判据、`next`、拒绝形状），codegraph 递出去的是"数据"**；

**我们自己的三处缺口**（都有原文依据，见 §5.1 ④⑤⑥）：`affected` 的**同名误报**（2/3）· `locate` 的**名额被测试文件占满**与**语料只读名字+doc** · 桥侧**没有"证明某物没动"的动词**。

**最值钱的五条引导**（完整 20+ 条在各题"引导含义"节）：

### 5.1 跨题模式（九条，每条给可复核的证据位置）

**① 我们递出去的是"数据 + 它意味着什么"，codegraph 递出去的是"数据"。**
同一问域下最锋利的一格是 `s3`：我们 `callgraph --orphans` 的返回里印着
`note 5 function(s) in test files have no static caller either; the test harness calls them, so they are counted here rather than listed above`
（`target/round9/logs/s3.jsonl` 第 3 条），答案是**抄的**（`target/round9/answers/s3.md:11`）；
codegraph 的对应输出只有 `Callers of "audit_unused" (0): … ℹ No callers found`（`target/probe-cg26/logs/s3.txt`）。
同类还有：`h2` 的 `a lapsed one needs a person to confirm the new state`（"要人、不是改代码"）·
`h3` 的 `wiring no declared cut … names root/control/dial — … a face no cut names is one the build replaces with nothing` ·
`g4` 的 `(the enum is private, so a constructor outside this tree cannot spell the variant either)` ·
`r4` 的 `pins no test names postable`。**这条决定了"边界声明"那一类分数由工具输出决定，而不是由模型自觉**。

**② 我们是"跑出来的"，它是"读出来的"。**
`s2` 我们靠 `check --face audit` 真跑：`verdict failed (cargo exit 101)` + `failed the_audit_counts_the_non_zero_entries` + panic 原文；
codegraph 那道题**一次 cargo 都没跑**（`target/probe-cg26/answers/s2.md` 末行自述 "nonbridge: 0 次 own"），答案来自
**非仪器的共享 `diff -r` 对上参照树 + 读 `#[cfg]` 推断**（推理原文 `dialogues/cg/_apparatus.md:1554`）。
`g2` 同形：我们真跑出 3 条 `failed`/`why`，它靠读断言预测红。

**③ 我们一次调用打包多种信息，它一次只答一个符号。**
`s1` 的 `callgraph {function}` 一次给"定义行 + 唯一调用者 + `(a test file; outside this file's directory …)` + callees + tests + 源码正文"
（`target/round9/logs/s1.jsonl` 第 2 条）；它要 `query`→`callers`→`node` 三次才凑齐。
`h1`（范围型）我们 **1 次 `check --census true` 给全 16 行普查表**（12 数据行 + 3 行 `not covered`），
它要 **14 次真实查询 + 2 `init` + 1 `files`**，而且"栏"（0 值栏、分母、逐目录、每栏盲区）**结构上没有对应物**。
`s3` 3 vs 20（其中 **12 次 `callers` 逐个生产符号**）· `g4` 3 vs 13。

**④ 我们自己的噪声源：`affected` 的同名误报。**
`s1`/`s4` 上 `affected` 报 3 个测试文件，其中 **2 个是 `Entry::new` 撞 `Store::new` 的同名误报**
（`target/round9/logs/s4.jsonl` 第 1 条；答案 ⑤ 不得不手写"其中 2 个是同名 `new` 的误报"），
agent 为此多花 2 次调用（`search --literal` + `read`）去推翻它；而"按名字匹配"这句免责声明**只印在 `check --census` 里**，
`affected` 自己的输出里没有。**这是本轮最该修的一处**（判据：同一份材料里，工具说得出这句免责声明，却不说给自己最需要它的那个动词）。
