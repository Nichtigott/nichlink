# g2 —（只读 s5 的树）这段渲染逻辑想做什么，以及实现与意图的差

① 症状：意图是"表头 + 条数 + 每条一行"，实现在这棵树里少了整块条数行。
② 伪代码（意图；依据 `render.rs:5` 文档 + `:7-13` 结构 + `write_count` `:17-19`）：
   `text = "LEDGER REPORT\n"` → `write_count(text, entries)`（写 `"entries: {len}\n"`，位于主循环**之前**）→ `for e in entries { text += "{e.account}: {e.amount}\n" }` → `return text`。
③ 实现与意图的差：`crates/report/src/render.rs:7 render()` 里没有这次 `write_count` 调用——`callees render` 不含它、`callers write_count` = 0 ⇒ 输出的第一块就是分录行，条数行整块缺失；`write_count`（`render.rs:17`）成了死函数。
④ 反证：`crates/report/tests/report.rs:35 the_report_prints_its_count_before_the_entries`（断言 `text.find("entries: 3") < text.find("a: -500")`）在这棵树上会先炸在 `:38 expect("the count line is printed")`，与"缺块"一致；若 render 真调了 `write_count`，它的 callers 不会为 0。
⑤ 同树第二处（不是渲染，但同源偏离，一并报）：`crates/report/src/query.rs:27` 写成 `if entry.amount > min`（应为 `<`）——过滤语义反向，`report.rs:20` 那条测试同样会红。
