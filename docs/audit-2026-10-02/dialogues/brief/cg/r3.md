# r3 — 注入缺陷（boundary-off-by-one）：桶的上界写成闭区间

① 症状：`cargo test --offline` **恰 1 条红**：`bucket_boundaries_are_half_open`（`tests/ledger.rs:92`，`left: "debit"` / `right: "small"`）。
② 根因：`src/store/index.rs:24` `Some(high) => amount <= high`——上界被写成闭区间；而类型自己的文档 `:11-12`/`:17-18`（"Exclusive upper bound / 有上界时严格小于它"）与 `buckets()`（`:34-36`：`{MIN,0}`、`{0,1000}`、`{1000,None}`）都要求**不含**上界。
   机制：`bucket_of(0)` 先命中第一个桶（`high=0`，`0 <= 0` 成立）⇒ 返回 `"debit"`，而 0 应落 `"small"`；同理 1000 会落 `"small"` 而不是 `"large"`。
③ 最小修：`index.rs:24` 改 `amount < high`（已在副本里应用；**9 passed / 0 failed，rc=0**）。测试与 `buckets()` 未动。
④ 反证：测试的四个断言是 -1→debit、0→small、999→small、1000→large；闭区间下**第一个**就错位（实测 left=`debit`/right=`small`），与"只有上界符号写错"完全相符。若缺陷在 `buckets()` 的边界常量上，999/1000 两条也会连带错位——可逐行核对 `:34-36`。
⑤ 调用清单：codegraph `node src/store/index.rs`（改前、改后）；`node src/store/index.rs` 的 `contains`/`bucket_of` 源码行；非 codegraph：`cargo test --offline` 两次（rc=101 → rc=0，per-tree `CARGO_TARGET_DIR`）。
