# s6 — 契约与实现一致吗

① 症状：不一致——`postable` 的实现与它自己的契约文档相反。
② 根因：`crates/core/src/model.rs:38` `self.has_receipt || self.amount == 0`；契约在 `model.rs:32-36`（"带凭据才可入账，零金额一律不可"）。
   反例（按实现真值表）：`Entry::new("a", 0, true)` → `true`（契约说零金额永不可入账）；`Entry::new("a", 0, false)` → `true`（无凭据也可入账）。机制：`||` 同时放宽了两条合取项，而 `Store::post`（`crates/core/src/store.rs:22-24`）只靠 `if !entry.postable() { return None }` 这一个判据把关 ⇒ 本应被拒的分录被收下。
③ 最小修/改动清单：`model.rs:38` 改成 `self.has_receipt && self.amount != 0`。
④ 反证：若 `post` 自己还做二次校验，症状就不成立——`node crates/core/src/store.rs`（`:21-27`）显示它只依赖 `postable`；`callers Entry::postable` 也只有 `post` 一个调用者。另注意本树没有覆盖这条契约的测试（report 套件无零金额用例），所以约定不靠测试兜底。
