# s8 — 条数行的位置
**① 症状** `check {face:default}` → `verdict failed (cargo exit 101)`：
`the_report_prints_its_count_before_the_entries`（`crates/report/tests/report.rs:40`）失败，
panicked 文本 `the count comes first:`。条数行**还在**，只是位置不对。只读，未改动。
**② 结论（文件:行号）** 条数行被写到了**所有分录行之后**（末尾），而意图是紧接表头、分录之前。
`crates/report/src/render.rs:7-14` 的 `render` 顺序是：`:8` 表头 → `:9-11` 逐条分录 →
**`:12` `write_count(&mut text, entries);`** → `:13` 返回。
契约在 `crates/report/src/render.rs:5-6`：a header, **the count**, then one line per entry
／表头、**条数**，然后每条一行；测试的 doc 更直白（`crates/report/tests/report.rs:30-33`）：
`What a reader sees first: the count, then the entries`／读者先看到什么：先是条数，然后是分录。
**③ 机制一句 + 证据** `write_count`（`crates/report/src/render.rs:18-20`，写 `entries: {n}`）本身没错，只是调用点排在循环之后 ⇒
渲染文本里 `entries: 3` 的偏移量大于 `a: -500` 的偏移量，`:40` 的 `assert!(count < first_entry)` 失败。
`callgraph {function:render}` 打印的源码把 `write_count` 放在 **`for` 之后**（与文件 :9-12 逐字一致）；
`read {path:crates/report/src/render.rs, whole}` 同序；`check` 的 `why` 行点名 `:40`。
（另两条渲染测试不红：`the_report_names_its_count_and_its_entries`（:44）只查 `contains`，
不查顺序；`the_report_prints...` 是唯一钉位置的一条。）
**④ 反证** 能证伪「位置错了」的观察：若条数行在表头之后、分录之前，`count < first_entry` 会成立、该条测试不会红；
实际它是本树**唯一**红的一条（另 2 条 passed），且 `render` 源码里 :9-11 的循环先于 :12 的调用。
另一侧：若条数行根本不存在（s5 那种缺件），`text.find("entries: 3")` 会在 :38 就 panic（`the count line is printed`），
而本树 :38 通过、panic 落在 :40 ⇒ 不是缺件，是次序。
**⑤ 调用清单（`target/round9/logs/s8.jsonl`）** - `check {face:default}` — failed，cargo exit 101；只点名 `the_report_prints_its_count_before_the_entries`。
