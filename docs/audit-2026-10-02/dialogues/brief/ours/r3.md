# r3 — 注入缺陷 3（boundary-off-by-one）
**① 症状** `cargo test --offline` 恰 1 条红：`bucket_boundaries_are_half_open`
（tests/ledger.rs:92，`left: "debit"` / `right: "small"`，exit 101）。
**② 根因** `src/store/index.rs:24`（`Bucket::contains` 的上界判定）：`Some(high) => amount <= high`。
桶是**半开区间**（`src/store/index.rs:4-5` 与 :11-12 的字段文档：high 是 exclusive；:17-18 的契约
「below `high` when it has one／有上界时严格小于它」），`<=` 让金额 equal to the upper bound 同时落进
相邻两桶；而 `bucket_of`（:42-52）按顺序取**第一个**命中的桶，于是 1000 与 0 都落到前一个桶：
0 ∈ [MIN,0]（"debit"）而不是 [0,1000)（"small"）⇒ 断言 0→"small" 得 "debit"。
**③ 最小修** `src/store/index.rs:24`：`amount <= high` → `amount < high`（1 行）。改后 `cargo test --offline`：
`test result: ok. 9 passed; 0 failed`，exit 0。
**④ 反证** 能证伪本诊断的观察：①若红因是桶边界表写错（buckets() 的 low/high），只改 contains 不会全绿；
②若这一行与红无关，改回 `<=` 不会重现红。实际做：改 1 行 → 全绿；再把该行还原成 `<=` →
只跑该条仍红（同 left "debit" / right "small"）⇒ 该行是唯一充分原因；还原修复后再次 9 passed。
另：`why` 只列出该定义处的契约行与调用者，`bucket_of` 的「首个命中即返回」在源码 :43-50 逐行核过。
