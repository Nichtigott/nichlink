# s7 — 分桶的上限含不含 1000
**① 症状** `check {face:default}` → `verdict failed (cargo exit 101)`：
`the_report_agrees_with_the_ledgers_own_limit`（`crates/report/tests/buckets.rs:17`）失败，
panicked 文本 `one amount on each side of the limit: ["bucket small"]`。只读，未改动。
**② 结论（文件:行号）** **含 1000**（且这是错的）：`crates/report/src/buckets.rs:10` 的判定是 `else if amount <= 1000`
——上界被写成了**闭**区间，于是 `bucket_name(1000) == "small"`；而两处意图都说 1000 属于**再上一档**：
- `crates/report/tests/buckets.rs:7-9`：`An amount exactly at the small limit belongs to the next bucket up`
  ／恰好等于小额上限的金额属于再上一档；
- `crates/core/src/limits.rs:4-9`：`SMALL_LIMIT = 1000`（:10）只写在这里，报表应从它读，别把数字再拼一遍。
  `buckets.rs:10` 正是把 1000 重写了一遍（census 也点名：`respelled 1000 ... written again at crates/report/src/buckets.rs:10`）。
**③ 机制一句 + 证据** `bucket_lines`（`crates/report/src/buckets.rs:19-26`）对每条分录取 `bucket_name`，再 `:24-25` 排序去重；
测试喂 `SMALL_LIMIT-1 = 999`（应 "small"）与 `SMALL_LIMIT = 1000`（应 "large"）两条，期望 2 行；
实现把两条都判成 "small"，去重后只剩 `["bucket small"]` ⇒ `:17` 的 `assert_eq!(lines.len(), 2)` 失败。
`check` 的 `why` 行与 `callgraph {function:bucket_name}` 打印的 `else if amount <= 1000` 与文件逐字一致。
**④ 反证** 能证伪「含 1000」的观察：若上界是开的，999 与 1000 会落进两个桶、`bucket_lines` 给出 2 行、测试不红；
实际红且输出恰是 1 行 `["bucket small"]`。另一侧：`bucket_name(1001)` 走 `else` → "large"（源码 :12-13），
说明只有**恰好等于** 1000 这一条被吞进 "small"，不是「所有大额都被算小」。
