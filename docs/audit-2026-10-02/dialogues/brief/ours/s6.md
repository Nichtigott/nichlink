# s6 — 契约与实现一致吗
**① 症状（问题）** 题面：契约与实现一致吗。只读，未改动。
**② 结论（文件:行号）** **不一致。** 契约写在 `crates/core/src/model.rs:29-36`：an entry is postable when it has a receipt,
**and a zero entry never is**／带凭据的可入账，**零金额的一律不可**。实现在
`crates/core/src/model.rs:37-39`：
```rust
pub fn postable(&self) -> bool { self.has_receipt || self.amount == 0 }
```
`||` 与「且 + 零永不」相反：**金额为 0 的分录（无论有无凭据）都被判可入账**。
（无凭据且金额非零时 `false || false = false`，仍被拒——所以偏离只在 `amount == 0` 这一支，不是「两个条件都反了」。）
**③ 后果与为什么没被抓住** 唯一调用者是 `crates/core/src/store.rs:22` 的入账守卫 `if !entry.postable() { return None }`，
即拒绝是**对外承诺**的一部分（:19-20 的 doc）。可是：
`why {at:crates/core/src/model.rs:37}` 明说 `pins: no test names postable — nothing pins this`；
树上没有任何测试 post 过金额 0 的分录（`crates/report/tests/report.rs:13-15` 三条都是 -500/500/5000），
`crates/core/tests/audit.rs` 里那条 `Entry::new("a", 0, true)`（:21）只喂给 `audit_count`，从不过 `post`
⇒ `check {face:default}` **passed（cargo exit 0）**：绿是「没覆盖」，不是「一致」。
**④ 反证** 能证伪「不一致」的观察：①若契约那几句只是描述别的东西，`why` 的 contract 行不会恰在该定义的正上方——
实际 `why` 把 `crates/core/src/model.rs:29-36` 当作该定义的契约打印；②若某条测试真的钉住 `postable`，
`why` 的 `pins` 行会点名它；实际为空。反之若我认为一致，则要解释 `0` 金额凭据分录被 `post` 接受
