## Queue / 待做

Ordered by severity, then by how much damage a silent failure does. Each item names
its angle id, the file, the smallest fix, and the pin a fix must turn red.

### CRITICAL

- **G1+G2 (gates) — purity escapes.** `purity::findings` scans each masked line for
  literal `std::fs`/`std::env`, so four independent bypasses were measured green on the
  load-bearing architectural rule: `use std::{\n env,\n fs,\n};` (both braces on one line
  only), `use std as s;` + `s::fs::metadata(…)`, `std :: fs :: metadata(…)` (spaces around
  `::`), and `option_env!("HOME")`/`env!`. Fix: scan the whole masked file as one string,
  collapse whitespace around `::`, handle multi-line brace imports (or walk `UseTree`s with
  `syn`), add `env!`/`option_env!`. Pin: a fixture with all four shapes must be red.
- **G3 (gates) — `lint` misses crate-root `allow`.** Keeping `#![warn(missing_docs)]` and
  adding `#![allow(missing_docs)]` disables the lint (last attribute wins) and passes;
  `#[allow(dead_code)] #[allow(missing_docs)]` on one line passes (the scan stops at the
  first `)`); `#[cfg_attr(all(), allow(missing_docs))]` passes. Fix: match `allow(` anywhere
  in masked text, scan to the *matching* paren, accept `warn`/`deny`/multi-lint forms,
  reject `allow`/`forbid` naming `missing_docs`. Pins: the three shapes above.
- **G4 (gates) — `mounting` misses `include !`.** `include ! ("x")`, a newline between
  `include!` and its delimiter, and `include/* c */("x")` all splice a module while the gate
  counts one `include!`. Fix: scan the whole masked file for `include` + optional whitespace
  + `!`. Pin: `pub mod spliced { include ! ("zz_body.rs"); }` must be red.
- **C1 (consumer) — published `nichlink-studio` fails its own `--all-features` suite.**
  26 `prototype-fixtures` tests resolve `studio/tests/fixtures/node-editor`, which is not in
  the tarball, while `studio/Cargo.toml` advertises the feature. Fix: move the fixture host
  under `studio/src/` (or package it), or stop advertising the feature as published. Pin:
  extract the package and `cargo test --all-features` must exit 0.

### MAJOR

- **P1 (plugin-host) — the signature does not bind the registration.** `signing_payload`
  covers the manifest + bytes but not `RegistrationInfo`, so after tampering
  `registration.flow`/`parent` a `Signature`-assured artifact still verifies, passes a
  contract check the honest artifact fails, and runs. Fix: include a canonical digest of
  `RegistrationInfo` in `signing_payload` (or sign the declaration) and verify it. Pin: sign,
  flip `flow`/`parent`, both verifiers must fail.
- **K3 (kernel) — `mask_non_code` has no raw-string rule.** `r#"…"#` with an interior quote
  leaks the rest of the literal as code; braces, `fn` and calls inside raw strings become
  real to the index and call graph (MCP + Studio). Fix: at `r`/`br`/`cr` + N `#` + `"`, skip
  to the matching `"` + N `#`. Pin: `direct_calls("let s = r#\"{\"k\": \"drop()\"}\"#;", "f")`
  must be empty.
- **K4 (kernel) — `function_source_range` starts on the raw line.** A comment or string
  containing `fn name(` starts a phantom range, and the name test is a raw substring
  (`new` matches `renew(`). Fix: evaluate the start test on `mask_non_code(line)` and require
  a non-identifier boundary. Pin: `["// fn ghost() {", "fn real() {", "}"]` → `None`.
- **K5 (kernel) — JSONL cannot round-trip non-ASCII.** The writer emits raw UTF-8; the reader
  rejects every byte ≥ 0x80 *and* every `\u` escape, so no encoding of `crate::héllo` is
  readable. Fix: decode raw multi-byte UTF-8 and implement `\uXXXX`. Pin: `from_jsonl(to_jsonl(g)) == g`.
- **S2 (surfaces) — MCP `read` overflow.** `(center + context)` overflows: debug panics,
  release returns `start > end` with `isError:false` — a wrong answer an agent would trust.
  Fix: saturating arithmetic plus a bound on `line`. Pin: `line: u64::MAX` never inverts.
- **S3 (surfaces) — CLI panics on non-UTF-8 argv.** `std::env::args()` unwraps; a legal Linux
  path with a 0xFF byte panics with a backtrace in every subcommand. Fix: `args_os()` and a
  clean error. Pin: spawn the binary with a non-UTF-8 argument.
- **S4 (surfaces) — `new --path <dir>` skips checkout validation.** An empty/nonexistent
  directory is accepted, exits 0, and writes a manifest with a path dependency that cannot
  resolve. Fix: apply the same predicate auto-detection uses (`core`+`build_method`+
  `run_method`). Pin: `new --path <empty dir>` fails and creates nothing.
- **C3 (consumer) — the scaffold cannot be published.** The `Local` dependency specs carry
  no `version`, so `cargo publish --dry-run` on a scaffolded project fails manifest
  verification. Fix: add `version = "0.1.0"` (the `Git` arm already does). Pin: scaffold →
  `cargo publish --dry-run` gets past verification.
- **C4 (consumer) — the scaffold cannot build inside a workspace.** The template writes no
  `[workspace]`, so scaffolding inside an existing workspace fails `cargo metadata`, `check`
  and `build` (the rehearsal script patches this by hand). Fix: emit `[workspace]`. Pin:
  scaffold inside a workspace with `members` and build.
- **G7 (gates) — `release_workflow` reads one file.** A second workflow can publish from a
  branch. Fix: run `findings()` over every `.github/workflows/*.yml` and flag any `run:`
  containing `--publish`/`cargo publish` without a tag guard, whatever the step is named.
  Pin: a second workflow with a branch-triggered `--publish` must be red.
- **G8 (gates) — the tag guard is a substring test.** `!startsWith(… 'refs/tags/')` passes
  (it contains the text), and a decoy step name lets the real upload go unguarded. Fix:
  require the positive conjunct and key on the step that runs `--publish`, not on its name.
  Pins: both bypasses.
- **G9 (gates) — `doc_blocks` rejects its own escape hatch and misses fences.** A
  ```` ```rust,macro-input ```` fence (the sanctioned tag, used by the audit docs) is reported
  as broken; `~~~rust` and ```` ```rs ```` fences are invisible; `hello: world` is accepted as
  struct fields. Fix: pass the tag list into the markdown handler, honour `macro-input`,
  accept `~~~`/`rs`/`Rust`, tighten `as_fields`. Pins: the tag must be green, the tilde fence
  red, the prose red.
- **G10 (gates) — no gate for the bilingual doc convention**, nor for "new pure logic is
  registered in `core/src/registry_core.rs`", nor for shim re-exports. An English-only
  `///` on a public item is invisible to rustc, clippy and every gate, and ships to docs.rs.
  Fix: a `doc_language` gate (CJK line required after the English lines on every `pub` item
  in the nine non-example crates), a registration gate, a shim gate. Pin: an English-only
  public doc must be red; an unregistered `core/src/registry_core/zzmodule/zzmodule.rs` must
  be red.
- **C5 (consumer) — the published 0.1.0 READMEs are stale** (`TraceMode::from_env`, missing
  `json` row, missing `snippets` row) because the README is part of the artifact and the
  release was cut before those fixes. Immutable; ships in 0.1.1. Record only.

## release-ci / 发布与 CI

- **R1 CRITICAL — the tag precondition and `--check-table` read the release version from
  the *first* `version = "…"` line of the root manifest and never read a member's resolved
  version.** Members all use `version.workspace = true`, which `version_problems`
  (`tools/nichlink-publish:323`) skips, and `workspace_requirement_problems` (`:370`) reads
  only the non-dotted `[workspace.dependencies]` section. Measured mutant: a centralized
  `[workspace.dependencies.nichlink-core] version = "0.1.0"` above
  `[workspace.package] version = "0.1.1"` → the tag step reads `0.1.0`,
  `--check-table` says "matches the manifests (9 crates)" exit 0, and `cargo publish`
  would upload **0.1.1** while the index wait polls for 0.1.0 — failing *after* the
  irreversible upload. Fix: read the version from the `[workspace.package]` section only,
  and check resolved versions/requirements via `cargo metadata --no-deps`. Pin: a
  `conventions` gate over the shipped manifests (shell-only pin impossible: these tools have
  no test harness).
- **R2 MAJOR — a multi-line inline table hides a wrong internal requirement.**
  `/^nichlink-[a-z-]+ *=/` and the `version` match are tested on the *same line*
  (`tools/nichlink-publish:348-357`), so `nichlink-core = {\n path = …, version = "0.2.0", }`
  passes while the inline and dotted spellings are refused. Fix: read resolved requirements
  from `cargo metadata`. Pin: the multi-line mutant must exit non-zero.
- **R3 MINOR — `is_published` ignores `"yanked"`** (`tools/nichlink-publish:175-188`,
  `tools/nichlink-package-audit:164-177`, byte-identical copies), so a yanked version counts
  as published and is reported `verified`. Fix: require `"yanked":false` on the matching line.
- **R4 MINOR — `for level in $levels` word-splits**, so the documented one-line-per-level
  batching never happens; a crate that does not reappear stops the release before its
  mutually independent siblings are attempted (`:518`). Fix: iterate lines.
- **R5 MINOR — both index-dependent gates conflate "index unreachable" with "not yet
  published"**: against a dead endpoint the package audit reports `verified: <1>` /
  `skipped: <8>` and **exit 0**, and the same for the dry-run publish. Fix: distinguish
  transport failure from 404 and exit non-zero when the probe could not run.
- **R6 MINOR — `tools/nichlink-package-audit` derives deps with awk/sed**, disagreeing with
  `--check-table` about the dotted and target-specific spellings, and never reads an inherited
  `readme`, `license-file`, `include`/`exclude`. Fix: derive from `cargo metadata`.
- **R7 MINOR — the `conventions` release-workflow gate matches hard-coded step names**, so an
  upload step with another name (or no `name:`) yields no finding — the regression detector
  cannot detect the regression (see also G8). Fix: select steps by the command they run.
- **R8 MINOR — `core/tests/nesting_budget.rs` ships and walks `CARGO_MANIFEST_DIR/..`**, so
  from a registry unpack it "passes" by scanning whichever unrelated crates are neighbours
  (measured: 294 files from nine extracted crates). Fix: take the root from an env var and
  skip when unset, or move the walk into `conventions`.
