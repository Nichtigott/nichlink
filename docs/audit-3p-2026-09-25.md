## Method note / 方法说明

**A new cross-crate public API makes the package audit red until the next release.**
`tools/nichlink-package-audit` builds each packaged tarball in isolation, so its internal
dependencies resolve from crates.io — the *published* versions. When the checkout adds a
symbol that another crate then uses (measured: `build_method::is_checkout` used by `cli`),
`cargo package` of the calling crate fails to compile even though the workspace is green,
and it stays red until a new version is published. Two consequences for this queue: a fix
that needs a new cross-crate symbol has to be paired with a version bump, and P1 (below)
is exactly such a fix.
**新增跨 crate 公开 API 会让包审计红到下个版本。**
`tools/nichlink-package-audit` 在隔离环境里构建每个包，因此它的内部依赖从 crates.io 解析——也
就是**已发布**的版本。当检出新增一个随后被别的 crate 使用的符号时（实测：
`cli` 使用 `build_method::is_checkout`），调用方的 `cargo package` 会编译失败，尽管工作区全绿，
而且它会一直红到发布新版本。对本队列有两点后果：需要新增跨 crate 符号的修复必须与版本线推进一起做，
