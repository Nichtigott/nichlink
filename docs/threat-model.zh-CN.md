# 威胁模型

[English](threat-model.md) | 简体中文

## 资产

- 宿主注册树及其父链、合同不变量；
- 插件字节、签名、校验和、lock 记录和撤销信息；
- 宿主进程及传给插件的数据。

## 信任边界

core 声明只是元数据，不执行插件代码。Studio 和 debug collector 是开发工具。Wasm 与进程适配器是独立执行边界；进程适配器每次调用使用新的子进程。

## 控制措施

- release 使用经过检查的 `StaticPlan`，不保留 inventory linker section；
- 外部注册面在发布前校验来源、框架、版本、父节点和合同闭合；
- 官方插件需要匹配信任策略和签名，社区/本地插件至少需要已验证 checksum；执行这条策略的路径是
  `nichlink-toolchain` 里的 `PluginAdmission`：它读取插件 lock，在任何 verifier 运行**之前**
  拒绝不在名单上的官方插件，并在校验签名**之前**拒绝已被撤销的版本。签名覆盖随插件字节一起传输的
  注册信息，而不只是清单；
- Wasm 限制线性内存、表元素、fuel、输入与输出大小，以及接受的工件字节数；模块还在引擎的严格限制下编译；
- 进程调用使用 framed I/O、输入/输出上限和硬超时，超时子进程会被终止。子进程以什么启动也由宿主
  决定：`ProcessLimits::inherit_env = false` 会清空环境，之后只有 `ProcessProgram::environment`
  点名的变量存在；`ProcessProgram::current_dir` 选择它在哪运行。默认仍然是继承，因此既有宿主的
  行为在它主动选择之前不变；
- 热替换在同一 generation 发布代码和 Registry，健康检查或 graft 失败会保留旧版本；
- 撤销和流程版本不匹配会在激活前拒绝候选。

## 剩余风险

普通库无法证明任意 Rust 动态分派、函数指针、FFI 和优化后局部变量的完整事实。MIR 候选和未观测值必须带证据标记并保守回退。Wasm 内存限制也不等于逻辑安全，应用仍需选择合适的合同和能力范围。

**进程**插件是这里最弱的边界：宿主给它的 I/O 分帧、限制输入输出与墙钟时间、终止超时的子进程，
也能清空子进程环境并选择它的工作目录。超时约束的是**这次调用**而不是进程树：宿主只终止直接子进程，
而那个子进程自己启动的进程不在这一组里——按组杀需要 `libc`——因此它可以带着宿主的 uid、环境、
文件系统与网络，在这次调用已被宣告死亡之后继续运行。它无法收窄的是访问权限：子进程仍以宿主用户的
身份访问文件系统与网络，因此环境与工作目录是**存在的两个旋钮**，而不是一个沙箱。README 的插件一节
这么写了，并明确否认沙箱；这一段是那句话的剩余风险半边。运行不可信进程插件的宿主必须在 NichLink
**之外**限制子进程——容器、用户或操作系统沙箱——因为本工作区里没有任何东西做这件事。
