# NichLink 路线图

[English](ROADMAP.md) | 简体中文

这份路线图只描述 NichLink 注册协议本身。NichUI 产品、商业运营和社区工作不属于这里的技术里程碑。

## 当前版本：0.1 early production

- [x] 被动递归 `Registry`、原子批量注册和 graft；
- [x] admission、结构规范和输入/输出合同；
- [x] 按目录发现注册面、身份缓存、粗修和 `StaticPlan`；
- [x] `off`、`errors-only`、`full` 三档运行时追踪；
- [x] Studio 的搜索、检查、数据、对比和源码跳转；
- [x] 只读 MCP 桥、经过校验的 Wasm/进程插件适配器；
- [x] 跨平台 CI、规模审计、符号审计和打包检查。

0.1 可用于实验和选定的内部生产项目，但不宣称能完整分析任意 Rust 程序。

## 下一步工程工作

### 1. 稳定证据格式

为调用边证据定义版本化格式，包含符号、源码位置、所属节点、证据类型和目标候选。证据过期或损坏时必须保守回退到全树，不能进行不安全裁剪。

### 2. 可选编译器适配器

提供独立的 nightly `rustc_driver`/MIR 分析器；stable 用户继续使用源码扫描。适配器输出候选和不确定性，不把候选冒充确定事实。

### 3. 单态化与间接调用

从宿主入口追踪泛型实例和方法。将 `dyn Trait`、函数指针、FFI 和地址逃逸表示为候选集合。实时 `CallTrace` 可以提升已发生的边，但不能静默删除无法解析的目标。

### 4. 构建与发布证据

把确认后的 scope 交给正常 rustc/LLVM/ThinLTO，再比较符号和产物大小。发布可复现的 debug/release 及 1 万、10 万节点基准。

### 5. 协议稳定化

冻结首批注册面字段，提供 schema 迁移，并让 `FaceManifest`、合同、admission、graft 和诊断格式都有版本且可独立测试。

### 6. 证据感知工具链

将 MCP 和 Studio 连接到 Registry 快照、合同、诊断及实时 provenance。每条结果都显示脱敏策略、信任状态和证据级别。

## 明确边界

普通依赖库无法保证解析所有动态 Rust 调用，也无法恢复所有优化后的未插桩局部变量。进程插件不是操作系统安全沙箱。依赖 crate 的 `build.rs` 不能读取宿主应用的 `main.rs`。

只有在测试、回退行为和基准证据都进入仓库后，里程碑才算完成。
