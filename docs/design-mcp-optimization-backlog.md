## 2. 待做项（P0 → P2）

每项格式：**现状证据 → 改法 → 预期 → 怎么自证（不靠外部测试）**。

### P0：有测量依据、改动小、直接消掉已知浪费

**P0-1 台账条目印 `recorded=<hash12>` / `current=<hash12>`**
- 证据 E6（18,177 字符 = 11.5% 的链花在重推内核指纹规则上）。
- 改法：`adopted` 与 `conformance` 在每条条目旁给出"记录值"与"当前重算值"，以及不匹配时**点名它匹配上了哪个文件的当前字节**（当能确定时）。
- 预期：那 1.8 万字符的推理在机制上不需要存在。
- 自证：h2 树上同一问，答案里两串哈希都在；把某个被覆盖文件的字节改一位 ⇒ 两串**不再相等**（反证）。

**P0-2 `read` 能读台账（或拒绝时给出替代调用）**
- 证据 E7：被拒 → `cat` → **那次调用不在我们的日志里**，我们的口径因此少算一次。
- 改法：允许 `.xirang/**` 与其它文本（或至少给出"台账请用 `adopted`，或加 `--raw`"）。
- 预期：消掉 1 次外流调用，并让口径完整。
- 自证：`read --path .xirang/adopted/entries` 出内容，且该调用出现在 `--log` 里。

**P0-3 `check` 附上失败断言原文**
- 证据 E8：它绕过我们去 `sed` 原始日志；而我们的代码里已经写着"下一跳去 search 那句话"（`check.rs:337`）——**我们知道少给了什么**。
- 改法：从 `check-<face>.log` 里把失败测试**紧邻的断言/painc 行**摘出（有限几行）附在回复里。
- 预期：h1 型入口少一次调用 + 一次 `sed`。
- 自证：h1 树上 `check` 回复含 `the_rendered_offsets_add_up` 的断言文本与退出码。

**P0-4 `read --whole` 带上符号行**
- 证据 E15：对照的 `node <file>` 一次给"源码＋行号＋符号数"；我们拆成 `read --whole`（源码）＋ `digest`（符号＋契约）**两次答案**——正是 E3 那种"两块事实分居"的形状。
- 改法：`read --whole` 的头部附每行的函数名／行区间／契约首行（把 `digest` 的那一栏并进来，复用同一份 `contract_lines`）。
- 预期：把"看全一个文件"从两次调用降到一次。
- 自证：同一文件，`read --whole` 的输出 ⊇ 原 `digest` 的符号与契约栏；字符数增量有界（≤ +30%）。

**P0-5 `search` 支持多名字串**
- 证据 E15：`explore "signed postable normalized_account zero_arm algorithms"` 一次给 25 行源码；我们 `search --query` 只吃一个名字、且只回位置不回源码。
- 改法：`query` 接受空格分隔的多个名字，按名字分组回 `file:line` ＋ 少量源码；单名字行为不变。
- 预期：h4 型"一个文件里全是名字"的题少 1–2 次调用。
- 自证：h4 树一条 query 覆盖三个名字，且单名字的既有答案键逐字不变。

### P1：有依据、改动中等

**P1-1 `check` 三条边界索引合并成一条**（E12：小题 47%）⇒ 每次 `check` 省 ~650 字符 ×（每轮重发）。自证：必需子串（`not a coverage measurement`、`not covered:`）仍在，`--census` 仍给全文。

**P1-2 `status` 的信息并进必经答案**（E14：7–8 次）⇒ `check` 首行／`consistency` 首行带上"这棵树 N 个面 M 个文件"。自证：同题上 `status` 调用数下降（目标 ≤2：一次开场都不需要）。

**P1-3 `next` 按状态实例化**（E13：采纳率 28%）⇒ 不再给 `read {path, line}` 这种模板，给**可直接执行的整命令**（真实路径/行号/node），并保证**每个读工具都有**（`adopted` 现在只有散文）。自证：采纳率上升；且用同一批 frozen 树跑改前/改后两版对照。

**P1-4 每个答案末尾一行"可引用证据"**（E5 的记账性重跑）⇒ 一行 `evidence <command> → exit N`，让 agent 引用而不必重跑。自证：下一轮"记账性重跑"计数 → 0。

**P1-5 `locate` 对文件级症状**（E11）⇒ 症状里没有标识符时，给候选**文件**（按 idx 里的名字密度）或明说"这是文件级症状，请用 `digest {file}`"。自证：h4 那次的同一问不再被判白跑。

**P1-6 `callgraph` 同名多定义时的取舍**（E9）⇒ 上限内按"离症状近/被测试点名/跨成员"排序，或把被扣下的名字连同行一起给。自证：9 个同名定义那棵树上，要找的那条在默认档内。

**P2-1 用修好的 h4 重建题树再跑一轮**（E2：这一轮的链长比被夹具缺陷污染）⇒ 链长比必须重新量。

## 3. 能推到哪：可消的与不可消的

**可消（有数）**：记账性重跑 2 → 0（P1-4）· 死胡同 2 → 0（已修）· 白跑 1 → 0（P1-5）· 台账外流 1 → 0（P0-2）· 边界 ~650 字符/次（P1-1）· `status` 5–8 次 → ≤2（P1-2）· "两块事实分居"造成的长块（P0-1、P0-4 各消一块）。

**不可消（也不该消）**：
- **题本身的语义工作**：即便 h4 夹具修好，"哪个算法与它自己的文档相反"仍需读契约与实现——那是问题，不是浪费。
- **构造反证 6 次**（E17）：那是加分项。任何"减少反证调用"的优化都是错的。
- **输入侧的 shell 成本**：建副本、跑测试、`cargo` 输出——不在我们工具的控制范围内（我们臂的 shell 输出 135,009 : 对照 101,407 字符）。
- **"能不能答"这一轴**：两臂都 4/4 全中（E15/E16）⇒ 差距**只能**出现在代价与形状上，别再指望"我们答得出它答不出"。

**一个诚实的下限估计**：46 次答题调用 → **35±5** 是可达的（假设 P0-1/2/3/4/5 与 P1-1/2/4/5 都落地且不引入新调用）。**但不能承诺"每题调用数 ≤ 对照"**：对照最省的地方正是"一次给整份文件"，而那是它的默认形状；P0-4 只是把我们的同类能力补到同一个水平线上。

同一批新题上同时满足：① 根因命中 ≥ 它 ② **每题调用数 ≤ 它** ③ token（**分输入/输出两栏**）不劣 ④ **推理字符**不劣 ⑤ 构造反证/最小性不劣。**证伪条件**：若配 codegraph 的称职 agent 也能全中 ⇒ 判无绝对优势（这一条 W8 已成立，下一轮默认成立，除非题目难度真的上去了——所以 P2-2 的新语料是关键）。

## 5. 明确不做

- 不做题库（题由构造给出）；不为省 token 删判据信息（边界、截断说明、拒绝里的形状行一条不删）。
- 不把需要"新增交付物"才能量的指标塞进现有题（会改变泛化能力，是维护者加的前提）。
- 不用"减少反证"换调用数；不追"调用数第一"而牺牲最小性与附带损伤的判定。
