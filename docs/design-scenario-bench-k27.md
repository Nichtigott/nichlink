# 场景对比 bench（kimi2.7 双臂）：规格

日期：2026-10-03。状态：预登记。本文是**判据与装置的冻结版**，跑分前不许改；要改先登记修正案。

## 0. 一句话

同一模型（kimi2.7）、同一 harness（Kimi Code 子代理）、同一任务书（逐字相同，除工具段），**唯一变量是 MCP 工具集**——我们臂走 `nichlink-mcp --call`，对照臂走 codegraph 1.6.1 CLI。量两条轴：**四轴 token 成本**与**交付物结构质量**（补丁感、骨架质量、算法自然度）。

选平价模型的理由（维护者原话）：很多人用不起能力强的模型——工具的价值恰恰是让平价模型也能高效准确地工作，所以**用平价模型测才是测工具**。

## 1. 与历轮装置的关系（吸收过的教训，逐条落实）

| 台账来源 | 教训 | 本 bench 的落实 |

## 2. 两臂与通道

**我们臂**：`target/debug/nichlink-mcp --call <tool> --root <树> --key value`（退出码 0 作答 / 1 拒绝 / 2 畸形）。
**对照臂**：`target/round7/tools-upstream/v1.6.1/bin/codegraph <cmd>`（init/query/explore/context/callers/callees/impact/sync…）。
两臂都允许：bash、grep、读树内文件、`cargo test`（`CARGO_TARGET_DIR` 树外）。这是刻意的——codegraph 没有写能力，它的臂**本来就要**靠 bash 写代码；禁掉 bash 就不是对比工具，是 disqualify。

**任务书纪律**：两臂逐字相同，只有"工具段"不同（我们臂写 nichlink-mcp 的调用方式，对照臂写 codegraph 的）。任务书里**不点名任何工具的使用策略**（不教路线——路线由工具的流程表/`--list` 自己供给，这正是被测对象）。

## 3. 测量

### 3.1 四轴 token（权威来源：子代理 wire.jsonl 的 usage 记录）

每个子代理会话的 `~/.kimi-code/sessions/wd_*/session_*/agents/agent-N/wire.jsonl` 里，每条 assistant 消息带：
`"usage":{"inputOther":A,"output":B,"inputCacheRead":C,"inputCacheCreation":D}`

| 轴 | 定义 | 字段 |
| --- | --- | --- |
| 输入总 token | 每步送入模型的全部 | A+C+D 逐条求和 |
| 未命中 token | 新处理/写缓存的输入 | A+D |
| 命中 token | 缓存读 | C |
| 输出 token | 模型生成 | B |

成本当量 = 未命中 × 10 + 命中（照 R10 口径）。子代理 `agent_id`（派发时返回）对应 `agents/agent-N` 目录，逐题求和无归属切分。

### 3.2 调用与形状（辅助轴）

仪器调用数（两臂各自的工具调用，从会话工具调用记录数）、步数、被拒次数、`withheld` 出现次数（截断代价）、白跑（未产生被后续引用信息的调用，人工判）。

### 3.3 质量轴（每题各自的机械判分键 + 横切指标）

**机械键**（逐题预登记在 §5）：根因 file:line、最小修、反证、`check`/cargo 绿、交付物必备行。

**补丁感指标**（横切，全部机械可判）：
1. **修复落点层级**：diff 落在根因**定义处** = 正；落在调用处/症状处 = 补丁（kernel 词法器判 diff hunk 的属主函数）。
2. **重复实现增量**：新增函数与既有函数的调用面重叠（`search`/grep 判同名或同调用集）。
3. **结构动作占比**：我们臂日志里 `apply *`/`graft` 次数 vs 裸写文件次数（对照臂无此轴，记 N/A——它的 N/A 本身就是数据）。
4. **跨轮回归**（多轮题）：修第 N 个 bug 后重跑前 N−1 个的反证，全绿才算不失控。

**结构质量**（S1 题）：骨架可编译、面树存在且层级符合任务书声明、`registry` 可读回、无多余文件。

**算法自然度**：代理指标（diff 行数、新增间接层数、函数平均长度）+ **盲评**（交付物打乱臂属后由评审者对"像不像人写的"打分，预登记评分锚点）。

## 5. 判分键（预登记，先导批）

**T1**：① `cargo test` 绿（树外 target dir）；② 存在 button 与 slider 两个对象的定义文件；③ 我们臂加判：`registry` 能列出两个面（cg 臂 N/A）；④ 结构质量按 §3.3；⑤ token 四轴 + 成本当量。
**T2**：① 答案点名根因 `file:line`（键在判分脚本，不写这里防泄）；② 修复 diff 落在根因定义函数内（补丁感①）；③ 反证：修复后该测试绿、且给出"改前红"的引用；④ 全测试套件绿。
**T3**：① 真值 `audit_unused` 被点名；② 测试函数边界被明确声明（"测试由框架运行期调用、不计入"或同等意思）——缺这半句记"部分对"；③ 与真值矛盾的断言单独记事实错误（scenario-plan 第 3 关 F1/F2 口径）。

**证伪条件（预登记）**：若对照臂在 T2/T3 上以不劣的成本当量交付同等质量的答案 ⇒ 判"先导批无优势"，扩批前必须先回答"工具供给的路线信息为什么没被使用"。若 T1 两臂结构质量打平 ⇒ S1 场景的工具优势主张降级为"未证实"。

## 6. 执行流程

1. 建 frozen 源：ledger 夹具固定 rev `git archive` 到 `target/bench-k27/src/`，记 sha256。
2. 逐题逐臂解树到 `target/bench-k27/runs/<题>/<臂>/tree/`，每题独立 `target/bench-k27/runs/<题>/<臂>/cargo-target/`。
3. 逐题派发子代理（一题两臂可并行——树独立、target dir 独立），任务书见 `target/bench-k27/briefs/`。
4. 收 wire.jsonl 求四轴 + 仪器计数；跑判分脚本（机械键）；质量指标与盲评随后。
5. 汇总表（照 `nichlink-compare-table.py` 的形状）：逐题 × 臂 ×（四轴 token、成本当量、调用数、判分结果、补丁感指标）。

## 8. 明确不做

- 不教路线（任务书不含"先用哪个工具"）；不为省 token 删判据信息；不用减少反证换调用数。
- 不跨模型对照（那是 dsh-agent-teams 的场景，本 bench 两臂同模型是刻意设计）。
- 不用 mtime 代替内容哈希；不把"没核验"说成"当前"（树的新鲜度照旧走 fingerprint）。
